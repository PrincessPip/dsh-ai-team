### 三态定义（这是整套机制的宪法）

| 裁决 | 触发条件（全部满足） | 后果 |
|---|---|---|
| **pass** | 验收清单每条都有**可复现证据**（file:line / 命令输出 / 截图路径）；无 blocking | 交付，工人进下一个任务 |
| **rework** | 问题能在**现有设计内**修：改代码、补测试、补文档；不动钱、不动权限、不动发布、不删数据、不涉及主观口味 | 带最小修改指令打回工人，最多 2 轮 |
| **escalate** | 命中任一：① 需要你取舍（产品/口味/优先级）② 涉及钱、账号、权限、对外发布 ③ 需求本身有歧义 ④ 不可逆操作 ⑤ 返工两轮仍不过 ⑥ 验收官置信度低或证据不足 | 打包成一份「你要做的一个决定」推给你 |

> 这套判据就是你原话「取决于问题的性质」的可执行版本。含糊的活不会漏给我，产品的活不会漏给你。

## 2.5 DAG 编排（**原文完全没有的一条线** · 2026-11-06 起 · 2026-11-12 补写）

上面的 A/B/C 三档回答的是「**谁来验 / 怎么批量验**」。真正让多个 AI 并行干活的第三件事是**编排**，
它在原文写完时还不存在 —— 现在有了，且是这台机器上唯一能跑多节点真任务的东西。

```
需求文本 ──► 经理层出图 ──► Gate 判据 ──► 执行器按波跑 ──► 证据包 ──► 产物核验
            manager.py      dag-gate     runner.py        runs/<id>/   verify-product.py
```

| 层 | 文件 | 一句话 |
|---|---|---|
| 经理层（出图） | `scripts/manager.py` · `manager.ps1` · `manager.schema.json` | 把一段需求翻成节点图（DAG），带 `writes` / `ctx.read` / `accept` |
| Gate 判据 | `scripts/dag.workflow.mjs`（`validate()`）· `scripts/dag-gate.mjs` · `scripts/graph-rules.md` | 40 个 code 的拒收规则；坏图不许进执行器 |
| 执行器 | `scripts/runner.py` | 六项语义 + **波内只读并行** + 三引擎 + 沙箱外置 |
| 证据包 | `runs/<id>/` | `BRIEF.md` / `GRAPH.json` / `GATE.json` / `RUN.json` / `NODES/` / `DIFF.json` / `FS-{BEFORE,AFTER}.json` |

**三个引擎**：`headless`（真模型、不写主树）· `fixture`（假 worker，秒级回归）· `codex`（ChatGPT 订阅，能写）。
**并行资格只认沙箱**：只有会被硬设成 read-only 的 `kind` 才进并波，写入一律串行留给唯一写手。

> ⚠️ **`result=pass` 只代表流程跑通，不代表产物对**。每个真跑单元另有一份 `verify-product.py`，
> 判产物必须跑它 —— 第三次真图（`tasks/SANDBOX-VERDICT-2026-11-10/`）才第一次拿到「流程 pass + 产物 pass」。

**真跑记录（三次，都是 `%TEMP%` 一次性副本内，主树不动）**：
① `tasks/DAG-2026-11-06/DELIVERY-e2e.md`（2026-11-09，`result=fail` —— 流程跑通、产物不对）；

## 4. 头号风险：验收官太容易说「OK」

LLM 当裁判有强烈的**顺从倾向**：它读了我写的漂亮总结，容易盖章。对策（写进契约，不靠自觉）：

1. **无证据即不通过**：每条 pass 必须引用 file:line 或命令输出，引不出就算 blocking
2. **先独立后对账**：让它先自己跑一遍验收命令、自己读 diff，**再**看我的自述；顺序反了它就只是复述
3. **默认怀疑**：「未验证」和「通过」是两回事，我写「应该没问题」的地方一律按未验证处理
4. **强制二选一**：不许输出「基本可以」「大致没问题」，只能是 pass / rework / escalate
5. **抽样交叉验证**：重要交付让我自己再复核一遍它的判据，防它编造证据（它会编 file:line）
