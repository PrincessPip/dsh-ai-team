> **事故单 = 救火队长唯一的输入。** 调用方式是**指路式**：引擎只收到这份文件的路径，

## 四、权限：写窄，读宽

### 4.1 写面白名单（文件级点名）

**只能改这些**：

| 路径 | 操作 |
|---|---|
| `{{精确文件路径}}` | 修改 |
| `runs/fire/{{INC-ID}}/**` | 新建（**新增产物目录是唯一允许的目录级授权**） |

> ⚠️ **格式是被机器读的，别改**：`scripts/fire-chief.py` 解析这一节的表格，
> **第一列必须是反引号包裹的路径**；解析不出来或出现 `{{` 占位符 → `exit 2`，不调引擎。
> `runs/fire/{{INC-ID}}/**` 这条**必须有**（它是产物目录授权，也是四件体检的落点）。

> 为什么默认文件级：目录级 token 太宽——`ledger-audit.ps1` 的 `decisions/` 一个 token
> 曾一次放行 8 个窗口内文件（`TRIGGER-POLICY.md` §二）。白名单宽一格，独立核就等于没做。

### 4.2 读面（**不设限**）

**整个工程仓随便读**：`Read` / `Grep` / `Glob` 全域可用，不必逐次申请。
需要时也可读 `~/.dsh` 下的具体路径（本单点名：{{…}}，没有就写「无」）。

理由：根因常在事故包**之外**——C7 卡三轮的东西就不在「要改的文件」里，而在证据怎么组织。
限读最贵的失败是**「在错误的前提上把活干得很漂亮」**，那种交付看上去完美，一验收全塌。

### 4.3 禁止

- 白名单外**任何**文件，包括「顺手修一下」；唯一另行声明的测试写面是 §4.5 已填实的工程外受管临时根。
- 下列**判据类**文件（`TRIGGER-POLICY.md` §二·五·五 硬红线：**能改干活的脚本，不能改审我们自己的判据**）：

  - `REVIEW-CONTRACT.md`（证据怎么算数）
  - `TRIGGER-POLICY.md`（什么该送审）
  - `decisions/self/ledger.md`（账本只能工人记）
- `git` 的任何**写**操作（`commit` / `checkout` / `reset` / `stash` / `clean`）。只许 `git status`、`git diff`。
- 不得修改本事故单。

### 4.4 读到了「意料之外」怎么办

> **只报不改。**

如果你在读别的文件时发现白名单外还有问题（这是好事，说明读宽有用）：

## 九、标准验收官（Opus 5.5 · 独立对话 · 带 shell · 唯一出裁决的人）
