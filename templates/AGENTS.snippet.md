# AI 团队约定（片段）

> **怎么用**：把这一节贴进你工作区的 `AGENTS.md`（或让 `ai_team_init` 铺成 `AI-TEAM.md` 再引用它）。
> 它只写**协作纪律**，不写具体项目事实 —— 项目事实留在你自己的 AGENTS.md 里。
> 贴之前删掉用不上的条目：**一条不执行的规矩比没有规矩更糟**。

## 角色：谁都不能给自己发合格证

| 角色 | 谁 | 能做什么 | 不能做什么 |
|---|---|---|---|
| **工人** | 执行任务的 AI | 实现、改文件、跑命令、自测、写交付包 | **不给自己发合格证**；不把自己的「已验证」当结论 |
| **验收官** | 独立会话的另一个 AI | 读文件、跑只读命令、逐条对账、出三态裁决 | **不写工作区**（纪律，非沙箱隔离 —— 越界靠事后快照发现）；不替人做产品 / 口味 / 花钱的决定 |
| **仲裁** | 人 | 在 `escalate` 时做一个决定 | 不逐条 review 日常交付 |
| **救火队长** | 外部 AI（可选） | 卡死后接手干活，写面限事故单白名单 | **不自审**；判据类文件禁改 |

**反例（明确禁止）**：工人自己调验收工具来验自己的交付。
工具不拦你，但三权分立那一刻已经塌了 —— 交付里必须写明「谁发起的送审」。

## 三态裁决：只许三选一

| 裁决 | 触发 | 后果 |
|---|---|---|
| `pass` | 验收标准**每一条**都有可复现证据，且无 blocking | 交付，进下一个任务 |
| `rework` | 有项不成立，但能在现有设计内修（不动钱 / 权限 / 发布 / 删数据 / 主观口味） | 带最小修改指令打回，最多 2 轮 |
| `escalate` | 命中六条红线之一、第 2 轮仍 `rework`、或 confidence < 0.6 | 打包成一个「需要人做的决定」 |

**禁止的措辞**：「基本可以」「大致没问题」「建议优化」「应该好了」。
这类词既不能驱动返工，也不能触发人的决定，只会让活停在原地。

## 证据纪律

1. **无证据不算通过。** 每条 `pass` 必须带 `file:line` 或命令输出。引不出 → 该条降为 `rework` blocking。
2. **证据要自报强度**（`E0`–`E3`）：
   - `E0` 断言（只有结论）→ 一律按未验证处理
   - `E1` 单点观察（1 条命令 + 1 次输出）
   - `E2` 可复现（同命令 ≥2 次一致）**或**双维（≥2 个不同观察类别）
   - `E3` 交叉 + **反证**（一个本该失败的情形，实测确实失败）
3. **同一类观察里换命令不算交叉验证。** `curl -s` 与 `curl -sv` 都只看状态码 = 仍只有一维。
4. **会跑的东西必须 `E3`**：脚本、配置、判据逻辑跑错了没人看得见。
5. **判断类条目上限 `E1`**，但必须写成**能被反驳**的形态（「我查了 X，结果 Y」），不许写「我认为没问题」。
6. **引用带锚串**：从目标行**逐字复制**一段 ≥8 字符的文本，规范化后唯一。行号只是缓存，会漂。
7. **证据由命令直接落盘**，不经手抄。手抄会转码、会「先写结论后做事」。

## 写作用域纪律

**共享 checkout 下，多 AI 同时写同一个文件必撞。** 没有任何机制能拦住你（详见最后一节），所以靠约定：

1. **一个交付单元只有一个写手。** 需要别人改的文件，用「请求」表达，不许直接改。
2. **开工前先认领**：在任务板 / 交付包里写明你要改的路径前缀（`writeScopes`）。
   两条作用域**前缀包含**就算重叠 —— 重叠告警是提示，不是锁。
3. **别碰别人的作用域。** 发现别人的文件确实需要改 → 停下来提请求，不要「顺手改一下」。
4. **判据类文件单独保护**：规则 / 判据 / 契约 / 闸门脚本属于「改错会静默污染后面每一次」的一类，
   改动前必须走送审，且**不许由同一个单元自批**。
5. **一次性产物**（运行输出、临时镜像、测试玩具）落在产物目录里，不落主树。

## 什么时候必须送审

命中任一条就跑独立验收，**不问**、不自己判断「这次小事不用了」：

1. **不可逆操作前**：删数据、对外发布、花钱、改账户 / 权限、动服务
2. **收敛型基础设施**：配置 / 插件 / 契约 / 策略文件 / 脚本入口
3. **跨文件一致性改动**：一个事实要同步到 ≥2 个文件（**按交付单元累计**，拆成 5 次单文件改动照样算命中）
4. **写不出可复现证据**：嘴上出现「应该好了」的地方
5. **返工后**：第 2 轮起，或修完一个真 bug
6. **人点名**

其余改动按**留存档**：工人自验 + 证据落盘 + 账本留一行。

## 账本

**任何改文件的操作都追加一行**（只读的活也要留一行，否则「我把这活标免检」这个动作本身无法被审计）：

```text
日期 | 改动文件 | 自判档位 | 命中的清单号（无则写「无」）
```

档位词只认 `免检` / `留存` / `送审`，处置标识只认 `更正` / `再更正` / `收口` / `救火` / `返工后送` / `补登`，
**都必须落在第 3 段开头**。正文里裸用 ` | ` 会毁掉行结构 —— 写表格片段时转义成 `\|`。

## 不许做的事

- 不许把「未验证」写成「通过」；不许把「没复现」写成「已修复」
- 不许补签凑绿：上一轮漏掉的判定，不许在下一轮悄悄补上当成通过
- 不许伪造证据引用（行号 / 命令输出 / 裁决文件路径）
- 不许在没听懂需求时「先把活干漂亮」—— 在错误前提上做得越好，验收时塌得越彻底
- 不许把「我不知道」升级成「规范里就是这么写的」

## 边界（别把约定当隔离）

这套约定是**提示词层面的**：它约束分工与纪律，**不做进程隔离**。
本机的多智能体框架（含 DSH 官方 agent-team）都没有 confinement —— 成员完全可以用 shell 写任何文件。
所以真正的兜底只有一条：**事后对账**（改动前后快照 + 账本对账 + 人抽检）。
把「约定」当成「硬锁」的那一刻，就是这套东西失效的时候。
