# 任务书 · REVIEW-BRIEF

> **这是验收官唯一的输入。** 他看不到你和工人的对话，也看不到账本上下文 —— 所以这份文件必须**自含**。
> 用法：复制成 `<交付单元>/REVIEW-BRIEF.md`，填完 §一 / §二 / §三 / §四 才能送审。
> 判据全文由调用方随任务书一起给（`docs/REVIEW-CONTRACT.md`），**本文档只写本单元特有的事实**。

## 二、要验收什么（逐条编号，每条都必须可判定）

> **每条都要能被回答「是 / 否」**。写「代码质量要好」这种不可判定的条目等于没写。

| # | 验收标准 | 类型 | 最低强度 |
|---|---|---|---|
| C1 | {{具体到什么文件 / 什么行为 / 什么输出}} | `fact-consistent` / `judgment` / `executable` | `E1` / `E2` / `E3` |
| C2 | {{……}} | | |
| C3 | {{……}} | | |

**类型怎么判**（先标类型，再谈强度）：

- `fact-consistent` —— 结论是「这个数字 / 事实在 A 和 B 处一致」「这个引用指得着谁」
- `judgment` —— 结论是对方案的定性判断（「这段够不够具体」「有没有洞」）。**上限 `E1`**，必须写成能被反驳的形态
- `executable` —— 结论关于脚本 / 配置 / 会跑起来的判据逻辑。**必须 `E3`**（跑错了没人看得见）

## 三、证据要求

**每一条 `pass` 都必须给下面之一，否则该条按未验证处理：**

- `file:line` + **锚串**（从目标行逐字复制的 ≥8 字符文本，规范化后唯一）
- 命令 + 输出摘要（**由命令直接落盘**，不是手抄）

**强度自报**：每条注明 `E0`–`E3` 与对应证据。分档规则见 `docs/REVIEW-CONTRACT.md` §二·五。

**特别要求本单元做的**（有就写，没有就删掉这一节）：

- [ ] {{例如：反证 —— 造一个本该失败的情形，确认它真的失败}}
- [ ] {{例如：跨位置核 —— 同一事实在 ≥2 个文件里一致}}
- [ ] {{例如：观察窗口 —— 凡有「稳定 / 不会断」这类断言，给 `WINDOW = <分钟>`（≥30，或已知最坏间隔）}}

## 四、你要做的判定

对 §二 每条落一个判定，然后汇总成三态裁决：

| 判定 | 含义 |
|---|---|
| `pass` | 有证据，且强度够了档 |
| `fail` | 证据不成立 / 强度不够（**缺的不是环境，是证据**） |
| `unverified` | 你没查。**不许算 pass** |

**红线**（命中任一条，裁决必须是 `escalate`，且必须在 `escalate_red_line` 里标编号）：

| # | 红线 |
|---|---|
| 1 | 需要人做取舍：产品方向、审美口味、优先级排序 |
| 2 | 涉及钱、账号、权限、对外发布、不可逆删除 |
| 3 | 需求本身有歧义，两种理解都说得通 |
| 4 | 工人与你的判断冲突，且已给过一次返工仍不成立 |
| 5 | 你无法验证（缺环境 / 缺数据 / 缺权限），且是关键路径 |
| 6 | 你自己 confidence < 0.6 |

## 五、输出格式（严格 JSON，不要多余的话）

```json
{
  "verdict": "pass | rework | escalate",
  "confidence": 0.0,
  "criteria": [
    {
      "id": "C1",
      "type": "fact-consistent | judgment | executable",
      "status": "pass | fail | unverified",
      "claimed_strength": "E0 | E1 | E2 | E3",
      "strength_met": true,
      "evidence": "file:line + 锚串，或命令 + 输出摘要"
    }
  ],
  "blocking": [
    { "id": "B1", "what": "问题一句话", "why": "为什么必须修（违反哪条标准 / 会坏什么）", "evidence": "证据" }
  ],
  "nonblocking": [
    { "id": "N1", "what": "可以之后再说的问题" }
  ],
  "rework_brief": "给工人的最小修改指令：改哪里、改成什么、怎么验。可执行、可验证、不含「优化一下」这类空话",
  "escalate_question": "仅 escalate 时填：要人做的那个决定是什么，二选一或三选一，各选项后果",
  "escalate_red_line": "仅 escalate 时填：命中的红线编号（1–6），多条写成数组",
  "reviewer_notes": "最多三句：你没能验证的地方、你的假设、你跑过的命令"
}
```

**`rework_brief` 在返工时必须写明本轮返工属于哪一类**（它决定被返工项的证据门槛）：

`事实存疑` / `判据可能没在判` / `修完一个真 bug` / `声明缺失` / `引用格式` / `材料形式`
—— **没写清时，按更严的一类执行**（fail-closed，不给套利空间）。
